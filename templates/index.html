OOM Investigation Guide for Podman & OpenShift
Key Metrics to Investigate OOM
  • container_memory_working_set_bytes: The critical metric used by Kubernetes/OpenShift kernel OOM killer. It represents active RSS + unevictable memory.
  • process_memory_rss_bytes: Resident memory consumed directly by Python code and native extensions (excluding disk caches).
  • container_memory_cgroup_limit_bytes / cgroup/memory.max: The hard limit set in pod YAML (resources.limits.memory). When working set hits this, Linux sends SIGKILL (Exit 137).
  • kube_pod_container_status_last_terminated_reason{reason="OOMKilled"}: Confirms pod was killed due to memory limit breach.
Recommended Tools
  • OpenTelemetry Collector: Ingests OTLP gRPC telemetry, batches, and exports to Prometheus.
  • Prometheus & Grafana: Scrapes metrics, graphs RSS vs limit, alerts before threshold breach.
  • OpenShift Web Console: Observe Observe > Metrics or Workloads > Pods > Events (Reason: OOMKilled, Exit code: 137).
  • memray / tracemalloc: Deep-dive Python memory allocators to find code-level memory leaks.
Quick CLI commands:
podman inspect --format '{% raw %}{{.State.OOMKilled}}{% endraw %}' <container>
oc describe pod <pod-name> | grep -E "OOMKilled|Exit Code"
